# Pull-Request-Checkliste

Eine kompakte Checkliste, um Pull Requests reviewbereit und nachvollziehbar vorzubereiten.

## Vor dem Review

- [ ] Der Pull Request verfolgt ein klar abgegrenztes Ziel.
- [ ] Ziel und Kontext sind kurz beschrieben.
- [ ] Relevante Änderungen und Risiken sind hervorgehoben.
- [ ] Automatisierte und manuelle Tests sind dokumentiert.
- [ ] Migrationen, Konfigurationen oder neue Umgebungsvariablen sind genannt.
- [ ] Screenshots oder Beispiele sind ergänzt, wenn sie helfen.
- [ ] Der eigene Diff wurde vor dem Review noch einmal geprüft.
- [ ] Debug-Ausgaben, temporäre Dateien und unbeabsichtigte Änderungen sind entfernt.
- [ ] Unfertige Änderungen sind als Draft erkennbar.
- [ ] Erforderliche Checks sind erfolgreich und Merge-Voraussetzungen geklärt.

## Grundsatz

Ein guter Pull Request macht ein Review leichter, bevor der Reviewer die erste Codezeile öffnet. Kleine, klar beschriebene Änderungen reduzieren Rückfragen und verkürzen Feedbackschleifen.
