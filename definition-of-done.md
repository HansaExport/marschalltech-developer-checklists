# Definition of Done

Eine Definition of Done schafft ein gemeinsames Verständnis darüber, wann eine Aufgabe wirklich abgeschlossen ist.

Diese Vorlage ist bewusst allgemein gehalten und sollte an Team, Produkt und Risikoprofil angepasst werden.

## Fachlich

- [ ] Akzeptanzkriterien sind erfüllt.
- [ ] Relevante Randfälle wurden berücksichtigt.
- [ ] Es gibt keine bekannten Blocker für die Nutzung.

## Code

- [ ] Implementierung ist verständlich und wartbar.
- [ ] Keine unnötigen Debug-Ausgaben oder temporären Lösungen verbleiben.
- [ ] Relevante Fehlerfälle werden behandelt.
- [ ] Sicherheits- und Datenschutzanforderungen wurden berücksichtigt.

## Review

- [ ] Code Review ist abgeschlossen.
- [ ] Offene Review-Kommentare sind geklärt.
- [ ] Vereinbarte Coding- und Architekturstandards sind eingehalten.

## Tests

- [ ] Automatisierte Tests wurden ergänzt oder angepasst, wenn nötig.
- [ ] Bestehende Tests sind grün.
- [ ] Relevante manuelle Tests wurden durchgeführt.

## Dokumentation

- [ ] Technische Dokumentation wurde angepasst, falls erforderlich.
- [ ] Nutzer- oder Betriebsdokumentation wurde angepasst, falls erforderlich.
- [ ] Änderungen an Schnittstellen, Konfiguration oder Migration sind dokumentiert.

## Auslieferung

- [ ] Änderung ist grundsätzlich releasefähig.
- [ ] CI/CD-Pipeline ist erfolgreich.
- [ ] Monitoring, Logging oder Metriken wurden angepasst, wenn nötig.
- [ ] Rollback- oder Fehlerbehandlung ist für kritische Änderungen bedacht.

## Grundsatz

"Done" bedeutet nicht nur "Code geschrieben". Eine Aufgabe ist erst dann abgeschlossen, wenn sie die gemeinsam vereinbarten Qualitätsanforderungen erfüllt und ohne versteckte Nacharbeit weiterverwendet oder ausgeliefert werden kann.
